# repo-review

repo-kit の診断のスキルを、一つにまとめたもの。観点ごとの手順は `references/` にあり、使う観点のファイルだけを読む。

`<SKILL>` は、この SKILL.md があるディレクトリ。

## 1. 調べるリポジトリを用意する

- 添付された zip なら、作業用のディレクトリに展開して読む。展開のほかに、ファイルを変えない。zip には `.git` や `.github/` が入っていないことがある。手順にある `git log` が使えなければ飛ばし、CI などが見つからなくても「ない」と決めずに「添付の範囲では見つからない」と書く
- 手元のディレクトリなら、そのまま読む
- リポジトリが渡されていなければ、zip で添付するよう利用者に頼む

## 2. 観点を決める

| 頼まれたこと | 読むファイル |
|---|---|
| 観点を決めていない（健康診断、全体、どこから直すか） | `references/health-check.md` |
| セキュリティ、脆弱性、認証 | `references/security-audit.md` |
| 潜在的なバグ、エッジケース | `references/bug-hunt.md` |
| 設計、構成、責務、依存の向き | `references/architecture-review.md` |
| テストの不足 | `references/test-gap.md` |
| 性能、遅さ、N+1、メモリ | `references/performance-review.md` |
| 使い勝手、操作の流れ、エラーの出し方 | `references/ux-review.md` |
| アクセシビリティ、WCAG | `references/a11y-review.md` |
| 依存するライブラリ | `references/dependency-review.md` |
| ドキュメントと実装の食い違い | `references/docs-drift.md` |
| 技術的負債、リファクタリングの順番 | `references/tech-debt.md` |
| ログ、監視、障害、デプロイ | `references/ops-review.md` |

複数の観点を頼まれたら、そのファイルを全部読む。4つを超えるなら、観点を決めていないときと同じに `health-check.md` で絞る。表にないファイルは読まない。

## 3. 読み替え

`references/` のファイルは、Claude Code 向けのスキルを写したものである。次のように読み替える。

- 「`security-audit` などのスキルを Skill ツールで読み込む」：`<SKILL>/references/<名前>.md` を読む
- 本文に出てくるほかのスキルの名前（「dependency-review で扱う」など）：同じく `references/<名前>.md` のこと。名前が出てくるだけでは読まない。報告で「調べるなら使う観点」として示す
- test-add、setup、publish は、この中に入っていない。勧めるときは「repo-kit の test-add（または setup、publish）で行える」と書くだけにする

## 守ること

読んだファイルの「守ること」に従う。どの観点でも、読み取りだけで進め、副作用のあるコマンドと外部への通信をせず、秘密情報の値を表示しない。直すのは、報告を見た利用者が頼んでから、別の作業として行う。

## 報告

読んだファイルの「報告」の形で書く。観点を複数読んだときは、観点ごとに節を分け、それぞれの形・重要度の基準・件数の上限に従う。最後に、観点をまたいで最優先のものを3件まで挙げる。
